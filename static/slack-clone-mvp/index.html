Brief: how the app works

Derived from the code and shared/CONTRACT.md at 7bc3701 plus the shared checkout at 2:30PM. Status key: Built committed; Partial code exists only uncommitted in the shared checkout, or one side only; Not built. Update 2:46PM: the boot, seq, notify and outbox work landed in 91d3a73 (backend) and 7d67bd8 (webapp); see section 2 for what is proven.

Three processes on one Mac. Electron main (desktop/) owns the window, the macOS menu, the Dock and tray badge, native notifications and the slack-clone:// link handler. It loads the webapp from a URL and talks to it only through a small preload bridge. The webapp (webapp/, React in the sandboxed renderer) owns all UI and client state: boot, the WebSocket, per-channel seq tracking, the send outbox, unread display and navigation history. The backend (backend/, one Node process) owns all data in one SQLite file and every rule: who can read what, mention resolution, seq allocation, read state, activity items and who gets notified. It holds every WebSocket in memory and fans events out directly. yarn start (desktop/scripts/start-all.mjs) starts all three.

(b) Life of a message

#StepStatus
1Composer generates a clientMessageId, shows the message as pending and saves it in the localStorage outbox.Partial
2POST /api/channels/:id/messages. A retry with the same clientMessageId returns the original (200) with no second fan-out.Partial
3Backend resolves mentions against the channel's members, then in one transaction increments channels.last_seq, inserts the message with that seq, stores mentions, writes activity items and advances the sender's read cursor. Note: mention resolution runs just before the transaction, not inside it.Partial
4Per recipient, the backend computes notify (skips the sender, DND on, notifyOn = none) and sends message.created in two serializations, notify true and false, from the in-memory hub.Partial
5Receiver drops seq <= highest, applies highest + 1, and on a gap fetches ?after=highest.Partial
6Unread: a top-level, non-system message above lastReadSeq bumps the channel's count; viewing the channel sends PUT .../read-state.Partial
7Recipients of mentions, replies or reactions get activity.created.Built (first contract); seq form partial
8If notify is true, the webapp calls window.desktop.showNotification; main shows a native notification whose click focuses the window and navigates through the command channel.Main: Built
Webapp: Partial
9The webapp sums unread mentions and DMs and calls setBadgeCount; main sets the Dock badge and tray title.Main: Built

3. API contracts

Source: shared/CONTRACT.md, shared/types/ and migrations 0001 to 0003, all committed (latest e5734ab). Base http://localhost:4000, REST under /api, WebSocket /ws?userId= opened only after boot. Acting user from X-User-Id (default u_alice); T routes take the workspace from X-Team-Id. Errors are { error: { code, message, retryable } }; clients retry only when retryable is true or on network failure, with full-jitter backoff random(0, min(30 s, 500 ms * 2^attempt)), max 5 attempts for sends.
